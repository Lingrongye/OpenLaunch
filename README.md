# OpenLaunch

原生、轻量的 macOS 启动台。采用 Swift + AppKit，独立实现类似 LaunchOS 的全屏网格体验，没有浏览器运行时和外部软件包依赖。当前针对本机 macOS 27.0（26A428）、内置触控板完成构建和初步验证。

## 使用

打开 `~/Applications/OpenLaunch.app`。也可打开工程内 `dist/OpenLaunch.app`。

- 点击应用图标启动；输入名称搜索，回车打开首个匹配应用；输入法组词过程中回车不会启动。
- Esc 清除搜索/返回根目录，再按 Esc 关闭；点击应用图标及名称之外的空白处也会隐藏，搜索框和分页按钮保持可用。左右键或滚轮翻页；分页点可点击。
- 默认 ⌃⌥Space 唤起/隐藏，设置可切换其他组合。
- 默认五指向内捏合打开（重复向内捏合不会关闭）；可改为三指、四指。本机系统三指拖移和四指捏合均开启，五指可减少冲突。五指全局唤起已获本机真人确认。
- 按用户当前需求，F4 暂停启用，设置中不显示相关授权入口。
- 四个触发角分别启用，可设置停留时间和 ⌥ 修饰键；出现系统触发角冲突时给出提示，不改写系统设置。
- 拖到另一应用图标中央创建文件夹，拖到文件夹中加入；拖到图标间隙排序；拖到网格左右边缘停留翻页。文件夹内右键“移出文件夹”。
- 右键可隐藏、在 Finder 中显示、移到上一页/下一页、重命名文件夹；设置可显示全部隐藏应用和刷新应用。

菜单栏九宫格图标提供设置、输入状态和退出入口。设置顶部可开启或关闭“登录后自动启动”，开启时登录后在后台运行，不自动弹出启动台。开关控制 `~/Library/LaunchAgents/local.openlaunch.login.plist` 及对应 launchd 启用状态，不结束当前进程。

## 数据与权限

布局位于 `~/Library/Application Support/OpenLaunch/layout.json`，图标缓存位于 `~/Library/Caches/OpenLaunch/Icons`。布局原子写入；扫描漏报不删除位置；损坏文件不会自动覆盖。设置提供明确的“备份损坏文件并重建布局”操作。输入触发记录只保留类别、次数和状态，位于同目录 `input-status.json`，不保存键入文本或触点轨迹。

基础浏览和启动无需输入权限；当前版本不请求 F4 输入授权。全局捏合使用动态加载的 Apple 私有 MultitouchSupport 接口，解析失败时停用该监听，其他唤起方式保留。它可能随系统更新变化，无法承诺跨所有版本兼容。

当前优先选择报告为 built-in 的触摸设备；没有内置设备时暂时选择第一个候选。带 Magic Mouse 与外接 Magic Trackpad 的台式机仍需设备选择增强与实测。

## 资源设计

- 隐藏时不绘制持续动画，触控板收到新帧才通过合并事件源唤醒。
- 触发角由鼠标事件和一次停留定时器驱动，无持续轮询。
- 当前页及前后相邻页共三个网格缓冲，连续跟手位移，松手吸附；惯性事件不会重复翻页。
- 图标在后台串行解码、栅格化并保存；主线程仅读取缓存和更新视图。Retina 按屏幕倍率生成，缓存上限180个/24 MiB，磁盘最多256张。
- 桌面壁纸后台缩小并模糊一次，翻页时复用静态背景，避免整屏持续实时模糊。
- 首次运行创建图标缓存，后续运行复用缓存；应用版本/修改日期变化会更新缓存。
- 目录扫描在后台执行，跳过嵌套 helper；相同 bundle ID + 版本按来源优先级去重，不同版本保留。

## 构建与验证

需要已有 macOS 命令行开发工具。无需安装 Node、Electron 或第三方 Swift 包。

```sh
swift test
./scripts/test-touch.sh
./scripts/build-app.sh
./dist/OpenLaunch.app/Contents/MacOS/OpenLaunch --smoke --output "$PWD/verification"
./dist/OpenLaunch.app/Contents/MacOS/OpenLaunch --probe-input
```

`--smoke` 使用临时布局目录，检查真实应用扫描、搜索、文件夹视图与持久化，并渲染程序自身的界面预览；不改变正式排列，不等同于真人拖拽/手势验收。`--probe-input` 验证动态接口、设备选择与权限，不能单独证明捏合成功。

构建生成本地 ad-hoc 签名的 .app，没有 Developer ID 公证；这是本机开发版本，尚非公开发行版本。具体执行证据和边界见 `verification/VERIFICATION.md`。

## 源码结构

- `OpenLaunchCore`：布局、保守合并、持久化与纯捏合识别算法。
- `ApplicationCatalog.swift`：应用发现与有界图标缓存。
- `LauncherWindow.swift`：原生网格、分页、拖拽、文件夹、搜索和设置。
- `InputController.swift`：输入权限、F4 校准、触发角与生命周期。
- `CTouch/TouchAdapter.c`：隔离的动态私有触点接口，固定大小缓冲和释放边界保护。
- `ShortcutController.swift`：Carbon 全局快捷键。

设计与实施记录在 `docs/superpowers/`。原程序调查与完整 REA Evidence 不包含在本仓库中。

## 0.2 界面与分页参考

参考 [macos-launchy](https://github.com/Punshnut/macos-launchy) 的7×5网格、比例留白、相邻页准备与图标缓存思路，独立使用 AppKit 实现，没有复制其源码或素材。参考快照 `faa508cc9cb92a0d26413c03569dd917052c7e15`。新界面采用更大的图标、居中搜索框和桌面壁纸背景。真人分页手感仍需用户实际确认。

## 0.2.1 输入与动画修复

分页仅轮换三个缓冲、重填最外侧页；手势期间移动Core Animation图层，吸附可从当前呈现位置中断续接。视觉残余位移不参与新手势的方向计算。鼠标高亮在复用、翻页和隐藏时清理。

本机发现系统四/五指启动台捏合与OpenLaunch同时启用，已在备份后关闭内置触控板的这两个系统开关，并重新加载Dock。备份在 `~/Library/Application Support/OpenLaunch/system-pinch-backup.json`。恢复原值可在工程目录执行 `python3 scripts/system-pinch.py restore`；系统可能需要重新加载Dock或重新登录后才生效。只改了这两个开关，没有改其他触控板手势。冲突处理参考 [macos-gesture-launcher](https://github.com/okruts/macos-gesture-launcher#disable-launchpadapps-pinch-gesture) 的说明；当前macOS27的实际效果仍需真人验证。

## 0.2.2 五指冲突与识别修复

仅写defaults并重启Dock未使本机输入驱动更新：实际IOHID参数仍为2。现在通过公开IOKit参数接口同步这两个启动台开关，并读回确认0；不改其他手势。scripts/system-pinch.py的disable/restore同时处理偏好与驱动，原始值保留在备份中，disabled_active标记控制应用启动/唤醒时的同步，restore会撤销此标记。

真人诊断确认五指被报告，但触点编号变化触发了严格拒绝。新识别器允许相邻不超过80ms、全体位置一对一连续匹配的编号变化，保留原始收缩基准、超时、位移和单次触发约束；指数量变化重新起算。

pinch-diagnostics.json只保存最近一段触点汇总的帧数量（监听重建前后可能合并，duration不等同一次物理手势的持续时间）、识别决策计数和汇总，不保存坐标轨迹、触点编号或键入内容。decision计数包含锁存状态重复，不等于重新编号次数；汇总spread比值也不替代识别器各连续段的收缩条件。

## 0.3.0 交互改进

捏合过程按收缩进度逐帧渐显和缩放网格；中途回张会降低进度，未完成就松手则回退隐藏，达到阈值后保持打开。采用自己的AppKit/Core Animation实现，遵守系统“减少动态效果”设置；不宣称与Apple启动台内部动画完全一致。菜单/组合键仍可切换显示，向内捏合仅打开。

点击图标图案启动，点击名称、图标间隙/背景隐藏。运动期间暂不接受鼠标图标/背景点击，避免展示图层与AppKit命中框位置不同造成误判。

应用名预先生成有界CGImage文字缓存（140项/6MiB），直接放到CALayer，与图标一起移动；不再等待离屏NSTextField在落页后绘制。保留tile的VoiceOver应用名称。

## macOS 27 原始触点采集与修复

本地验证时采集的触控板动作数据仅保存在验证目录中，不随源代码发布。原始回调显示同一帧的不同触点会重复报告 `fingerID`；而 `pathIndex` 在连续五指帧中保持唯一且稳定。旧适配器将重复 `fingerID` 判为损坏帧并永久停用监听。现改用 `pathIndex` 作为当前触点编号，并继续校验编号唯一、坐标有效和帧格式。该字段选择来自macOS 27内建触控板实测；私有ABI仍可能随系统改变。

## 0.3.3 快速捏合与指针命中修复

触控板回调现在进入有界先进先出队列，主线程逐帧读取并在队列非空时续唤醒，避免快速捏合只看到末帧或把释放与下一组手势合并；队列溢出会重置识别基准并在诊断中计数。悬停高亮及启动点击按图标实际alpha像素命中，名称、透明边缘和网格空隙都会关闭；分页按钮仍能操作。搜索字段改为整高布局并微调占位文字基线。

## 0.3.4 快速捏合提交与方形悬停

移除识别器对捏合持续时间的80毫秒下限。快速手势达到比例收缩和绝对收缩双阈值后立即提交，避免先渐显、松手却因未提交而隐藏。图标悬停底色独立绘制为围绕图标本身、四边等距的方形，命中仍限于图标实际alpha像素。

## 0.3.5 短行程捏合与搜索栏对齐

激活阈值调整为相对收缩22%且绝对收缩0.025（归一化触控板坐标），仍须五指连续、触点稳定，短行程快速捏合更容易提交。悬停正方形按图标与文字的可见尺寸共同计算，并留等距边距。搜索栏单独垂直居中标题绘制区域，并校准控件在胶囊中的位置。

## 0.3.6 固定应用卡片尺寸

同一网格中所有悬停高亮使用相同正方形尺寸和相同标题最大宽度。标题固定最多两行，过长内容在末行省略；图标与标题整体下移，为上方高亮留出空间，避免顶行裁切。

## 0.3.7 放大并居中应用卡片

统一悬停方框边长比0.3.6增加8pt，并在网格单元中水平、垂直居中；单元格边缘保留至少2pt空间。图标与最多两行的名称作为整体居中，避免顶部裁切。

## 0.3.8 图标中心高亮

高亮方框现在以图标中心定位，不再受应用名称影响；边长统一并按图标在单元格中的位置限幅，保证方框围绕图标等距且不越界。

## 0.3.9 增大图标中心高亮

高亮方框继续以图标中心定位，边长增至网格单元短边减4pt；标题与方框保持独立布局。

## 0.3.10 首行高亮不裁切

图标在单元格内下移以增加顶部空间，同时保留标题可见；高亮方框仍以图标中心为准，并按可用空间计算最大边长，避免首行圆角被裁切。

## 0.3.11 方框微调下移

在0.3.10基础上，仅将高亮方框向屏幕下方微移4pt；图标与名称位置不变，边长按调整后的位置限幅以避免裁切。

## 0.3.12 方框再下移2pt

相对0.3.11将高亮方框再向屏幕下方微移2pt，其他布局不变。

## 0.3.13 修复搜索框无法输入

显式启用原生搜索框的编辑与选择能力；点击和键入应用名会实时过滤列表。烟测现在会先将焦点移出搜索框，再模拟真实点击、输入和筛选，避免只给控件赋值而漏掉不可编辑的问题。

## 0.3.14 搜索文字与光标居中

搜索输入使用原生单行高度，并在48pt胶囊内垂直居中；胶囊内留白也可点击聚焦。烟测同时测量空输入和键入应用名后的光标位置，验证其中心与胶囊中心的垂直差不超过3pt。

## 0.3.15 点击与启动反馈

图标按下时缩小并加亮，松开后回弹、显示高亮边框；启动较慢时高亮轻微呼吸，启动完成、关闭、拖拽或复用时清理。为让反馈可见，打开应用前保留220毫秒的确认动效。键盘回车和辅助功能激活使用相同启动反馈，并阻止启动等待期间重复打开。系统“减少动态效果”开启时只显示静态高亮。

## 0.3.16 自启设置

设置顶部新增“登录后自动启动”复选框，每次打开设置时读取实际配置；更改失败会提示并重新读取状态。关闭后当前 OpenLaunch 继续运行，之后登录不再自动启动。

## 0.3.17 应用中文名称

启用跨 bundle 本地化资源读取，按系统语言优先使用应用提供的本地化名称（例如“调度中心”“备忘录”“音乐”）；缺少本地化名称时回退到原始名称或文件名。搜索同时匹配显示名称、原始名称和不带扩展名的文件名，保留英文检索能力。仅更新显示与搜索，现有应用排列和文件夹保持不变。

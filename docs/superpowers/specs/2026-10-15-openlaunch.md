# 独立启动台替代项目：待确认设计

日期：2026-10-15。暂定名称：OpenLaunch。该设计已由用户确认，现已实施首个本地版本。

用户已确认第一版优先“尽量还原 LaunchOS，包括触控板捏合、F4 和触发角”；以下已把三种唤起方式加入第一版范围。用户追加要求：低占用、快速、简洁且尽量还原。

## 三种路线

1. Swift + AppKit 原生重写（推荐）：NSWindow/NSCollectionView 控制网格、分页、焦点、拖拽，NSWorkspace 处理图标与启动；工程量适中，便于针对本机 macOS 27 验证。
2. SwiftUI 为主：原型较快，但复杂拖拽、跨页移动与全屏焦点需要额外桥接；本机旧 LaunchOS 也有这类实现。
3. 选择现有开源启动台再改造：可能加速，但先要独立评估代码、许可证和本机兼容性；本轮未审计候选项目，不能把它作为已确认捷径。

## 第一版

- 当前屏幕全屏图标网格；正常应用入口与菜单栏入口；不会自动加入开机启动。
- 扫描 /Applications、~/Applications、/System/Applications 和实际存在的系统应用来源；跳过 app 内部嵌套 helper，按路径和 bundle 标识处理重复。
- 显示真实应用图标和名称，中文/英文文本搜索，Enter 启动，Escape 返回或关闭，左右翻页。
- 手动拖拽排序、创建/重命名文件夹、移动应用进入/移出文件夹，右键隐藏应用与在 Finder 中显示。
- 可配置全局快捷键与 F4 唤起：同时覆盖普通 F4/Fn+F4 和键帽对应的系统功能事件；在用户启用 F4 接管后，仅过滤已确认的目标事件，避免启动台与系统功能同时弹出。
- 全局触控板捏合唤起：提供 3/4/5 指设置；普通两指缩放不触发。优先验证本机事件数据是否包含稳定的触点信息，再确定输入适配接口；不能把仅在本应用窗口内收到的 magnify 事件当作全局捏合成功。
- 触发角唤起：四角单独启用；以鼠标所在屏幕为目标，可配置修饰键和停留时间；离开角落后重新武装，避免持续开关。检测与系统触发角冲突并提示，不自动改写系统设置。
- 布局写入独立 Application Support 目录，带版本号，原子保存；加载失败保留损坏文件，报错并允许恢复，不自动重置。
- 使用系统模糊视图作为背景；核心路径避免使用 CGS 私有接口和原程序 Dock 插件。

## 组件和数据流

ApplicationCatalog 发现 app → LayoutStore 合并持久化顺序与分组 → LauncherWindow/GridController 呈现 → 用户搜索/拖拽 → 更新布局并保存。LaunchService 用 NSWorkspace 启动选中的真实 app；HotKeyService、TrackpadInputAdapter、GestureRecognizer、HotCornerMonitor 统一交给 ActivationCoordinator 控制窗口开关。

应用条目保留 bundleIdentifier、URL、显示名；分组保留稳定 ID、名称、子项 ID；可见顺序由布局控制。扫描与 UI 更新分离，图标按需加载与缓存。应用不存在时保留布局引用并标为不可用，避免一次扫描失败清空排列。

## 后续增强

多屏独立布局、旧系统启动台数据导入在后续版本加入。第一版不包含卸载清理器、许可证服务、自动更新和遥测。

## 三种唤起方式的证据与技术设计

### 捏合

本机原程序 InputEventMonitor 附近有 initialCentroid、initialSpread、previousTouchs、fingerCount、lockThreshold、movementThreshold、maxPinchDistance、pinchIn、pinchOut、idle/possible/tracking 等字段，并导入 CGEventTapCreate、CGEventTapEnable。它们支持“以触点分散程度变化判断捏合，使用状态机过滤误触”的推断，但不能证明具体输入事件编号、API、阈值或公式。

替代实现将输入获取与手势算法分开。算法可采用触点质心 c=Σpᵢ/n，平均半径 r=Σ||pᵢ-c||/n，以相对初始半径的收缩比例形成进度；这是拟采用的算法，不是已恢复的 LaunchOS 源码。指数量稳定、足够收缩后确认；抬指、数量变化、超时或系统状态变化时重置；一次手势最多触发一次。排除两指缩放、普通滚动与掌触，检测与三指拖移、系统四指捏合的冲突。

AppKit 的普通窗口触摸/放大事件不是全局多指捏合的充分方案。先做限时、仅含触点数量和归一化位置的诊断，确认 macOS 27 上的可用输入路径；不记录文字键入。若需要未公开接口，集中在可禁用的输入适配器中，解析失败时关闭该监听并保留其他唤起方式，不让输入组件导致整个启动台退出。未完成实际诊断前，全局捏合状态必须标记为待验证，不允许用窗口内缩放或按钮代替交付。

### F4

区分普通功能键 F4、Fn+F4 与键帽关联的系统功能事件；事件类型和数值必须通过本机诊断确认。公开 Carbon 快捷键用于正常快捷键，必要时使用 CGEventTap 处理指定系统输入事件。仅在权限满足、目标事件确认且设置启用时接管；去除按住产生的重复触发。用户关闭接管、权限撤销或事件监听失效时，恢复原事件传递。输入设备差异保留在适配层，不硬编码本机一次观察为所有键盘行为。

### 触发角

使用鼠标位置与每个 NSScreen 的 frame 判断角落，正确处理负坐标、多屏拼接和屏幕重排；普通鼠标全局/本地监听协调，避免重复回调。停留达到阈值后触发一次，离开触发区域才允许下一次触发。显示器插拔后重建配置，休眠恢复后重建监听。先读取系统触发角相关配置诊断冲突，不改写用户设置。

### 权限与系统状态

三种输入模块分别展示启用状态、权限缺失和监听错误。F4/全局捏合如需权限，由首次启用功能触发授权指引；不为基础网格强制请求权限。macOS 27 的具体权限分类与请求结果以本机实际 API 检查为准。权限撤销、事件 tap 被禁用、睡眠唤醒、切换用户、全屏应用和多屏分别验证；不通过不断重试掩盖权限缺失。

官方更新日志曾多次修复 F4、睡眠后手势和 macOS 27 手势状态问题，因此这些是第一版的验收项，不是可忽略的细节。

## 验收

真实 app 扫描与启动；搜索与键盘操作；跨页排序与文件夹行为；退出重开布局保留；损坏布局文件不会被覆盖；快捷键冲突可诊断；本机 macOS 27 启动与多屏/Space 检查。额外必测：

- 启动台未显示、其他应用处于前台时，选定 3/4/5 指捏合能够唤起；一次手势只触发一次，普通两指缩放/滚动不误触。
- 本机键盘默认模式与“F1/F2 用作标准功能键”模式下分别测试 F4 和 Fn+F4；开启接管时不会同时弹出系统目标，关闭接管后恢复原行为。
- 触发角覆盖四角、停留、退出再进入、修饰键，以及系统触发角冲突提示；外接显示器存在时另测负坐标与屏幕重排。
- 休眠唤醒、权限撤销/恢复后分别测试，不能仅用模拟事件判定真实成功。

输出独立源代码、构建脚本、可运行 .app 和逐功能已验证/未验证清单。捏合尚未通过真实全局手势验收时，不称为完整的 LaunchOS 替代版。

## 已确认范围

建议采用路线 1，第一版包含上述三种唤起方式。开始实施后先完成输入兼容性探测，再建设网格与数据层；先验证最不确定的全局捏合输入，避免网格完成后才发现关键体验无法交付。

## 性能实施与验证口径

原生 AppKit、无外部运行时；事件驱动的触点合并源；当前页渲染；固定96像素图标、有界内存/磁盘缓存。分别记录 .app 字节数、进程物理占用、RSS、空闲 CPU、冷启动与暖唤起调用耗时。调用返回时间不是用户感知全链路时延，真实手势不以合成输入代替。
